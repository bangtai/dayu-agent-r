## 4. 当前源码的同源因果链与 owner

1. `hkexnews_downloader.py:list_report_candidates` 获取官方分类 raw，交 `select_hkexnews_report_candidates`；HK 不消费 `pdf_download_gate` 获取期间原件，也不接收本地 HK 正文。`_parse_announcement` 归一标题、分类、披露日、URL，不产生正文事实。
2. `cn_report_selection.py` 是 raw → 资格、财年/身份/覆盖、去重、candidate 的唯一业务 owner。当前 `resolve_hk_report_period` 只收 title/category/annual_ends；`業績公佈` 可以得到 results 家族和分类 Q2/Q4 信号，但无直接日期且 `_hk_title_years` 为空，最终 year=None，resolver 返回 None。`E/owner-observation.json` 与本轮 selection 均证实四条同样失败。即使提供已有年度末日期，也不能为没有报告截止日/年份的本条来源捏造其年度。
3. selector 在 unknown 分支直接保留 source_id/filing_date、report_date=None，不构造 candidate、不请求该来源 HEAD。`download_report_pdf` 只接收已确认 candidate；workflow 只对选中的 candidate 运行下载/转换/commit。因此后续 Docling 无法反过来提供这四份尚未准入 PDF 的期间。这是具体的信息依赖缺口。
4. `hk_fiscal_calendar.py` 负责直接截止日正规化和可信年度日历运算；不拥有来源获取、报表主体识别或披露日期猜测。本轮对**实际第2页原文短语**调用 `report_end_date`，四个日期均能正确规范化；没有改标题或向 selector 注入伪标题。
5. durable owner 仍是 `cn_download_source_upsert.py` 通过 source 仓储发布；manifest 由 storage 同源投影，filing event/result 读 candidate，CLI/job/wait 消费统一结果。当前 `hk_report_date_source` 将所有非空 HK 日期视为 source_title，不能继续套用于新正文日期。
6. `hk_download_rebuild.py` 及 `local_hk_annual_ends` 当前同样只读来源标题；只给下载入口加正文逻辑会导致日后 rebuild 丢失正文期间、年度证据不能复用、来源标记错误，属于禁止的下游补偿，计划必须一起覆盖。

f975 的 9633 改动是主报告与明确附属引用的有限作用域；四个本轮标题既无引用也无年份，不能靠该改动补齐缺失输入。相关 downloader 与 calendar 的源码仍与旧版相同，selection/rebuild 的实际差异已保存 patch；本结论由本轮当前源码与官方数据重新形成，未默认旧结论适用。

## 5. 建议的最小单 slice

行为结果：对**官方 results 家族、唯一主体、仅缺年度/截止日事实且无既有冲突，并在领先第1–3个物理页内具有受支持本期声明**的来源，受治理地取得原件并确认期间；同一个 owner 结果用于新下载、年度供证、跳过校验和本地重解析。三页是能力边界，不是任意 PDF 的安全或完备保证；决定性声明仅在预算外、预算内不足以消除主体/期间歧义时仍 unknown。产品代码仅在计划复审及 root 放行后实施。

### 5.1 事实产生与校验

- 在 Fins pipeline 设一个窄的 HK 正文事实 owner：输入官方原件 bytes、期望的规范股票身份；输出 typed 直接截止日、明确的年度/六个月业绩性质、PDF SHA、页号和原文见证，或封闭的不可确认结果。网络与仓储不进入这个纯事实模块；它不推断中期财年、不承担 candidate 或 publication 治理。
- 用 PDFium 直接提取领先第1–3页的物理页文本。三页是本 slice 明示的领先报表取证预算（四份实际决定性证据都在第2页，第3页为同报表续页），不是任意全文搜索。只接受明确本期综合收益/全面收益表的直接期间标题，或当前本集团本期业绩宣告及相邻报表语义；不从比较列表头、股息日期、会议日期、签署日或任意引用取日期。同一受支持作用域内的完整本期声明须唯一一致；重复相同事实可合并，冲突不能按出现顺序选一个。
- 对首页可识别股票代码与官方 raw 身份做匹配；跨来源、URL/摘要错配或明确身份冲突拒绝。缺少受支持本期声明、仅扫描图、错码、非支持期间、主体歧义均不产生确认事实。禁止硬编码公司/source/日期、把正文拼成假标题、跨 parser 投票或 pypdf 失败后猜数字。
- PDFium 是此能力明确选定的提取器，不运行隐式多 backend 恢复。若直接 import 它，应在 pyproject 明示现有受控依赖并保持平台 lock 一致；不新增 Poppler 产品运行依赖，不修改 Docling 当前转换策略。用当前真实原件做 extraction contract 回归；第三方缺类型信息应在真实窄边界约束，不以 Any/getattr/忽略错误逃避类型检查。
- **原生生命周期采用单请求独立 spawn 子进程隔离**。直接证据 `root-pdfium-concurrency-observation.json` 证明 PDFium 非线程安全且 Fins job/direct 可并发。当前 `docling_converter_factory.py` 装配 `ProcessDoclingConverter`，其转换在子进程；但 Web 的 `web_fetch_orchestrator.py` 经 `dayu.documents.docling_runtime` 同进程转换，不能假定本进程没有其它 PDFium。已安装 Docling 的 PDF 两后端/outline 共用 `docling.utils.locks.pypdfium2_lock`，另有 DOCX/表格/演示图像转换直接使用 PDFium；新建 Fins 私锁不能保护这些调用。
- 最小 owner：`dayu.documents` 的窄页文本提取边界拥有原生句柄及提取 worker target，不感知 job；Fins 拥有正文业务事实、进程调用及取消编排。worker 单请求、单线程、不加载/调用 Docling、不复用进程、不把原生对象传回父进程；所有 PDFium 调用（打开、页数、page/textpage、文本读取及关闭）均在该 worker 顺序执行，与父进程、其它提取请求和 Docling worker 隔离。进程机制只复用 `dayu.runtime.interruptible_process` 的 spawn、等待、中断和 bounded close，不复制进程平台，也不把业务或第三方依赖放进 runtime。
- Fins 调用边界接入现有 Host 取消观察；启动前、等待结果及接收结果后检查取消，取消后不得确认/提交。原生提取进行中由既有进程中断/回收机制收口，不靠线程超时后遗留 worker。正常及异常路径在 worker 的 `finally` 按 textpage→page→document 关闭，不依赖 GC；强制终止则须确认 OS 资源回收。父侧验证返回协议/摘要，始终回收进程及临时资源；启动、崩溃、IPC、提取、关闭/回收失败保留 typed 原因，不能伪装成功或吞成无正文。原文不支持仍是 source unknown。此方案不引入共享原生锁，故不存在锁等待；若实施改选锁，须先补审同进程全部调用共享同一锁及可取消等待的证据，不能擅换私锁。

### 5.2 唯一期间 owner 与冲突规则

- 扩展统一 HK resolver 的**显式 typed 正文事实输入**，不能只在 downloader/workflow/CLI 特判。原始 title/category 保持原文；正文证据以 source 身份和 SHA 绑定单条 raw，不能借另一报告的事实替本条补年。
- `cn_report_selection` 是正文 acquisition eligibility 的唯一语义 owner：对同一去重/窗口 raw 先返回封闭判定，至少区分「已确认」「仅缺年度/截止日事实、可获取正文」「冲突/歧义或不支持、保持未决」「非目标」。可获取分支携带对应 raw source key 与已通过校验的 results 性质；失败分支携带 typed 原因，不能把通用 `None` 当准入。downloader 只消费这个判定运输 bytes，再把绑定事实交回同一 selection owner 完成 resolution；两个接口复用同一主体/歧义判定，不能跨接口重算准入。
- 原有主体、直接日期、年份/财年标签、分类及投影 guard 必须在正文获取判定之前生效。多主体/竞争主体、未解截止日、区间简写、多个标题年份、显式年份/日期冲突、分类家族歧义或标题/分类投影冲突，连正文 PDF 获取都不触发；不能因可解析正文而覆盖。分类与正文年度/中期性质冲突、正文与可用标题直接事实冲突、变更年结日或年度锚冲突均失败关闭。标题已充分的路径保留既有事实行为和原报告/输入作用域，不扩大为全文审查或顺带改旧标题回退规则。
- selection 在同次 resolution 内分阶段处理：标题/本地年度事实按既有契约取得，本批正文年度先完成直接事实确认及身份/性质/月末/冲突校验，再合并可信本地年度、同窗标题年度和**本批已确认正文年度**为统一同公司年度锚集合，最后映射中期。不得逐条边消费边添锚；排序/倒序/任意排列结果一致。正文年度锚保留原件 source key、URL、SHA 与页见证；本地锚另保留 document_id/revision，使新增锚可回溯到原件。冲突锚不靠挑选顺序消解，受影响中期关闭。
- 六个月正文只有在 `relevant_annual_end_dates` 有可信锚且 `fiscal_quarter_at` 返回一致的财年/Q2 时才确认；彻底无锚、锚月份冲突、非月末或非支持边界均 unknown，**正文路径绝不进入现有标题路径的「结束月份＋季度序数」无锚回退**。复用既有常规月末日历，包括有可信依据的普通非十二月年结；不得为四样本硬编码六月/十二月，也不扩大特殊/过渡财年或52/53周支持。结果仍使用既有 Q4→FY/Q4、Q2→H1/Q2 投影。
- 统一 typed resolution 承载财年、身份/覆盖、report_date、两种来源语义及所用年度证据引用；正文事实、来源绑定、运输 witness 分离，不造包含业务与治理所有字段的 fact bag。candidate、年度供证、unknown、rebuild 和持久化消费同一结果；不再各自重新解析标题日期或把任意非空日期当 source_title。具体最小类型拆分由实现者决定，不搭建通用规则框架。

### 5.3 获取、原件交接、增量与失败

- downloader 仍只负责 HTTP/raw/资产运输；准入规则和正文事实解析调用 pipeline owner。仅对上述 selection 封闭判定中的 eligible 来源做 PDF 获取，使用既有 provider PDF gate、throttle、取消检查和 typed HTTP/PDF 校验；正文提取的原生进程同样受取消治理，不得绕过 Host。
- 可沿用 `prepared_assets` 的同次原件交接形状，但当前 `CnReportDiscoveryResult.__post_init__` / `require_matching_cn_annual_asset` **只接受 CN FY**，不能直接塞 HK 资产或关掉校验。扩展为显式允许「原有 CN FY」与「带已确认正文证据的 HK results」两种受限分支。最小 typed 链为：正文事实（日期/性质/SHA/页见证）→绑定证据（规范公司、provider/source_id、原 URL、正文事实）→selection resolution 对应 candidate；discovery 显式携带这些对应关系，不只留在 downloader 私有状态，也不要求把所有原文塞进 candidate。
- **models 的公共绑定校验是交接唯一 owner**：`CnReportDiscoveryResult.__post_init__` 对每个正文 candidate 要求恰有一份匹配证据，并恰有 prepared 或 local publication 一路交接，不得重复、遗漏或串源；比较 candidate/resolution 的日期/性质/来源、provider/source_id/URL，证据公司与显式传入的本次查询规范公司核对（当前 candidate 不含公司，不能声称凭 candidate 相等就已校验）；核实际 bytes 的长度及 SHA 等于正文事实 SHA（不是仅核 asset 自身 SHA）。CN FY 原 provider/身份/来源/长度/SHA/时间校验全部保留。提交/skip 边界由 filing workflow 复用同一公共校验，校验实际将发布或保留的原件；writer 内再核 publication revision/完整性，不能仅靠 downloader 私有断言。
- 为后续普通增量，workflow 仅经 source snapshot 读取**已发布、完整、正文来源的 HK 来源原件**，提供 source_id/URL、实际 bytes、opaque revision 的窄输入；provider 不持仓储。已存在的原四份标题来源报告无需为本能力读取/重传 PDF。建议把现有 CN-only 本地原件及只读 publication 运输类型改为准确命名的 CN/HK 共用窄类型，`local_cn_annual_pdfs` / `local_annual_publications` 一次迁到显式 `local_report_pdfs` / `local_publications`；校验仅允许原有 CN FY 与本 slice 的 HK 正文 results，CN 行为保持。全部构造点同步迁移，不保留旧名别名、extra payload、第二套同义 witness 或独立缓存真源。这是需审核的明确契约变更，不是顺手扩充其它市场能力。
- 本地证据与当前 raw 必须精确绑定，仍需重新核原文；仅看到同财年资产不算本条来源证据。local witness 要显式绑定已确认正文事实 SHA 与该 snapshot 的 document_id/revision/URL，由同一公共校验核读回 bytes；prepared 与 local 两路均拒绝「A 选期/B 落盘或 skip」以及同 provider/source key 不同 bytes，即使长度相同。跳过前、writer 内核当前 revision/完整性和已确认事实，陈旧 witness 走已有有限重试/冲突机制，不能授权覆盖或修旧资产。没有可用本地原件时按本次远端获取流程取得，不以已存派生财期代替事实。
- 新正文获取的 HTTP/非 PDF 协议失败保持 typed discovery 失败，不能伪装为空集合或成功；取消原样传播。可读取 PDF 但事实不足/冲突则该 source 保留 unknown，其他已确认候选可按现有机制处理，终态仍遵守 uncertain→partial_failure。未知不进入持久化，也不授予来源身份。

### 5.4 发布、所有消费者与 schema 边界

- 直接事实、财年/覆盖及来源标记由同一 resolution 向 candidate、event/result、source meta 投影。`hk_fiscal_calendar` 唯一定义 HK `report_date_source` typed 值域 `source_title | source_document | None`：依次表示标题直接截止日、原件正文直接截止日、没有直接日期；resolution 明确选择来源，投影 helper 消费该来源，不由日期非空与否反推。models/upsert/rebuild/processed 复用此定义，不各写字符串；CN 日期行为不变。
- `fiscal_year_source` 保留现有 title/CN 路径值；新正文年度使用 `source_document`，意为正文直接年度期间所给的年度结束年份。新正文中期使用 typed 新值 `source_document_and_annual_end`，意为「本条正文直接截止日 + 同公司可信年度日历推导财年」，不得说正文直接给出了财年标签；models 拥有封闭财年来源类型，selection 按正文及 calendar 运算结果产生来源，candidate 与各消费者复用该类型/投影。中期所用锚的 source/SHA 引用随 resolution 保留，不能只保留无来源日期。以上最小值域与投影交本轮受影响面复审。
- 用已发布原件、现有 `pdf_sha256`、source_id/URL 和确定提取规则形成 durable 可重核依据，禁止手改 managed meta。不得新增持久字段、新库或旧库兼容；页号/原文与细化 typed 绑定属运行期证据，不据此偷偷扩 durable schema。
- 优先复用**现有持久字段**（report_date、report_date_source、fiscal_year、fiscal_year_source、覆盖、来源及 PDF SHA）保存结果，不为本任务另造持久证据数据库或必填全库字段。页号/原文见证由事实 owner 产生，开发取证保留；若实现需要把它们公开持久化，则属于额外 schema 决策，必须先补充计划审核，不能以默认值兼容旧数据。
- 新 typed 输入/结果、来源值域、prepared/publication 分支和提取生命周期是本计划的重要契约扩展，须复审；不是一次标题正则小修。所有受影响生产构造点和测试按新契约更新，不保留旧签名 shim。若实现证明必须新增持久字段或有其它 durable schema 决策，先向 root 报告补充计划审核，不在本 slice 自行实施；不能以 bump 标签为由设计迁移或改写生产原四资产。
- `local_hk_annual_ends` 保持纯事实输入函数：接收既有同公司完整来源观察及同一 owner 已确认、带来源绑定的正文年度事实，不自行访问仓储/网络、不从 meta 日期盲信年度。原件读取和 snapshot→typed facts 接线属于 workflow/rebuild；provider 不持仓储。`hk_download_rebuild` 通过仓储读取正文来源原件并调用同 owner，年度先校验、统一建锚、中期后映射，纯本地不联网；正文与元数据/摘要/身份冲突不得静默退回标题或擦除日期。snapshot 到 batch 的 revision 须核一致，不能拼接 published bytes 与另一版 staging meta。没有原件或完整性失败按现有失败/未决契约处理，不强行成功。
- 当前控制路径中 `period_resolution_version` / `period_resolution_sources` 仅由本地 rebuild 写入，不是普通下载准入条件，也无以其触发迁移的读取分支。保留标题 rebuild 的 `hk-period-v3` 及原 sources 投影行为；正文 rebuild 用独立规则标签 `hk-period-body-v1`，表示本计划的受限正文/年度日历重解析规则，不是源码 commit 或资产内容版本。复用现有 `period_resolution_sources` 字段及 document_id 值形状，正文路径记录本次校验并输入日历的年度来源 document_id 去重排序集合（含正文年度来源，不意味着每条都参与该中期推导）；本条正文以自身 source_id/URL/pdf_sha256/来源标记可追溯，resolution 另保留实际邻近锚引用。普通下载不为标签新增写入路径或字段，其已发布年度原件可在本地重核并映射到这些 document_id。标签仅在后续显式 rebuild 该正文来源时投影，不做全库 bump/迁移；上述语义和新增值一并复审。
- source/manifest、已有 processed 投影和 direct/job/CLI/wait 对相同已确认事实必须一致。rebuild 必须在原事务边界同步有需要的 source/manifest/processed 字段，保持内容指纹和文件内容；正常新下载继续走既有 commit owner。UI、Service、调用方不得重算期间或添加 fallback。

此 slice 包含 owner、运输/存储接线、相应测试及必要文档，不能机械拆成互不闭合的多个实现 slice。无需先引入一个独立的全文解析平台。
