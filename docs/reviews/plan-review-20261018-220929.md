## Findings

### 1-未修复-中-统一 family 判断未定义 uncertain 投影在非目标数据上的语义边界

- **位置**：计划“一个 implementation slice”第一条最小方向（“将 category-first 的 report/results 家族判断和年度证据准入收敛到同一真源”）、“重要契约与边界”、风险表“统一家族准入可能影响其他 results 标题的 unknown 集合”。
- **问题类型**：契约缺失 / 状态机漏洞 / 范围漂移风险。
- **当前写法**：计划要求把 category-first 家族判断与年度证据准入收敛到同一真源，但对 `is_hk_report_family` 的**第二个消费者**——`select_hkexnews_report_candidates` 的 uncertain 投影——没有说明预期语义。风险表只把它列为“双路 planreview 核对语义；owner 反例测试和最终完整 code review 验证”。
- **反例/失败场景**：某非目标 HK 公司有一条官方 category 含 `業績`、但 title 不含现行任何期间/家族 token 且无法解析期间的 raw（例如仅有模糊标题或缺失日期）。修复前 `is_hk_report_family` 为 `False`，该行被静默忽略；若实现按“统一家族”把 category 纳入 family facts，则该行为 `True`，`resolve_hk_report_period` 为 `None` 时进入 `uncertain_hk_period`，整个普通增量变为 `partial_failure`/exit 1。相反，若实现为了保持旧行为而让 uncertain 路径继续用旧判断，则 owner 内仍有两套 family 语义，计划声称的“同一真源”并未达成。
- **为什么有问题**：`is_hk_report_family` 同时服务“年度证据准入”和“uncertain 投影”两个语义不同的消费者；计划只证明了目标两条 annual raw 需要前者放宽，没有证明后者也应同步放宽。计划冻结的 27 行 0388 数据在该路径上没有区分力：本 review 用自然 category-first 补丁重放 27 行，family 仅翻转两条目标年度结果行，且两条都 resolve，因此 11/0 的回归测试**不会**暴露 uncertain 投影行为的变化。
- **直接证据**：
  - `dayu/fins/pipelines/cn_report_selection.py:357-363`：`is_hk_report_family` 为真且 `resolve_hk_report_period` 为 `None` 时产出 `FinsDownloadUncertainReport(reason_category="uncertain_hk_period")`。
  - `dayu/fins/pipelines/cn_report_selection.py:970-999`：同一个 `is_hk_report_family` 被 `hk_annual_end_date` 先行调用。
  - `dayu/fins/download_contract.py:655-668`：uncertain 计数直接决定 `PARTIAL_FAILURE`/`FAILED`。
  - 计划风险表原文：“统一家族准入可能影响其他 results 标题的 unknown 集合 | fixed in current slice（计划归类） | 双路 planreview 核对语义；owner 反例测试和最终完整 code review 验证，不作公司特例”。
  - 本 review 的 27 行重放：当前 9/2；自然 category-first 补丁后 remote-only 11/0；family 翻转仅 `12030670`、`11548890` 两行。
- **影响**：实施 Agent 可能无意扩大其他 HK 公司的 unknown 集合，造成用户可见的 `partial_failure` 回归；也可能为了规避风险保留旧家族判断，导致“统一 owner”目标未完成、两套语义继续漂移。最终会表现为回归测试通过但真实行为边界未被验证，或 review 无法验收。
- **建议改法和验证点**：
  1. 在计划中明确 `is_hk_report_family` 在 uncertain 路径的预期行为：若接受“results category 但期间不可解 ⇒ uncertain”的扩大，明确写出该用户可见影响，并新增 owner 级测试：`category` 含 `業績`、title 无期间 token、期间不可解 → `uncertain_hk_period`；纯 `股息或分派`/董事会日期/非财报 category → 仍被忽略。
  2. 若要求保持 uncertain 集合现状，将 category-first 年度证据准入抽成窄 helper 供 `hk_annual_end_date` 使用，`is_hk_report_family` 的 uncertain 语义保持不变，并在测试中锁定该边界；这样仍可复用同一分类结果，但明确区分“年度证据资格”和“unknown 投影资格”。
  3. 在 27 行真实 raw 回归之外补一条非目标反例，避免 0388 数据“恰好全部 resolve”掩盖该边界。
- **修复风险（低/中/高）**：低（只涉及一个窄纯 helper/判断的语义说明与一条反例测试，不改变目标修复方向）。
- **严重程度（低/中/高/严重）**：中。
- **状态/分类**：accepted-candidate（契约/边界歧义，需总控裁决；不构成对目标根因或单 slice 方向的否定）。

## Open questions

1. **组合 category 的股息标题是否可作为年度证据？**  
   本 review 在内存中验证：自然 category-first 修复会把合成的 `category="公告及通告 - [末期業績 / 股息或分派 / ...]"`、`title="截至2025年12月31日止年度的第二次中期股息及暫停辦理股份過戶登記手續"` 判为 `family=True`、projection `Q4`、`annual_end=2025-12-31`；纯 `公告及通告 - [股息或分派（公告表格）]` 仍被排除，中期 combo 仍为 Q2 且不提供 annual_end。计划冻结的 27 行中股息行均为纯股息 category，因此计划要求的“股息不被错误采纳”测试不会自动覆盖该组合。  
   **需要总控/实现明确**：官方 `末期業績` category 本身是否足以作为年度证据（日期仍是财年截止日），还是必须增加 title 准入检查并加入组合 category 反例测试。若选择后者，应写成 owner 级行为断言，不能用纯股息行代替。

2. **`hk-period-v3` 审计版本是否需要随 resolver 输入准入变化而更新？**  
   计划明确“不要为强制刷新它们机械递增 `hk-period-v3`”，且现有 9 份来源的财期事实确实不变、目标两来源未入库、普通下载不写 `period_resolution_version`。但 `hk_download_rebuild.py` 的 rebuild 会在新的 annual evidence 准入下重投影并写同一个 `hk-period-v3`；未来若有人运行 rebuild，审计版本无法区分新旧准入逻辑。  
   **需要总控裁决**：保持 v3（计划当前选择，理由是现有事实不变、避免机械刷新）是否满足审计语义；若不足，应只对受影响的 rebuild 路径定义版本策略，而不是让普通增量强制刷新。

3. **真实 CLI 验收的外部依赖性**：计划预期 `exit=0` / 11 discovered / 2 downloaded / 9 skipped / 0 uncertain，并正确声明“网络或新增披露改变时保存差异、核对实际 raw 后裁决”。本 review 未运行真实 CLI；若 Docling、HEAD、PDF 获取或写入失败，计划允许保留真实失败诊断，这与任务书一致。该问题不是 plan blocker，而是 implementation 时必须如实记录的 residual risk。
