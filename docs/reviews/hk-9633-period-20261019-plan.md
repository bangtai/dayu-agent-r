### 同源根因复现

[`inspect_owner.py`](../../workspace/tmp/hk-9633-period-20261019/inspect_owner.py) 将冻结的**同一官方行**交给当前生产纯函数；结果见 `owner-evidence.json`：

1. `_hk_report_family` 正确得到 `report`，provider 没有丢失标题、分类或年份。
2. `_classify_hk_period_projection` 把分类和**整条标题**合并扫描：`has_h1=true`，去除半年报短语后 `has_fy=true`，因此返回 None。
3. `_hk_title_years` 对整条标题取得 `{2025, 2026}`，`_infer_hk_fiscal_year=None`；`resolve_hk_report_period` 的多年份约束也拒绝。两条拒绝原因均直接成立，不是只修其中一条就够。
4. 输入空年度证据或 `2025-12-31` 年度证据均返回 None。原文期间已确认，但这次拒绝并非年度截止日不足；不通过补日历来绕过。
5. `_is_hk_amended_title(原标题)=true`，因为附属引用里的“補充”命中全标题扫描。当前材料尚未进入 candidate，因此**没有声称已发布错误 amended**；但单独放开财期会把引用报告的补充性质带入主体，并经 `build_cn_filing_ids` 的 amended seed 影响新文档身份。选优也消费同一判断，必须一并收口。
6. 明确标识的诊断对照：仅取原标题中主体片段 `2026中期報告`，现有 resolver 返回 `(2026, H1/covered=(H1,))`，amended=false。该对照不是官方原行、不是补丁、不是修复通过证据，只隔离附属引用造成的影响。

因此不能采用“取第一个/最大年份”“分类压过标题”“忽略所有第二年份”“全局删掉补充字样”或公司/source 特例。也不需要增加 PDF 自动财期抽取、通用财年框架、网络旁路或下游兜底。

1. 保留 category-first、同 ID 冲突、语言、年度证据窗口及现有歧义约束。只在能够完整识别“唯一主体报告 + 明确指向另一报告的补充资料关系”时，限定身份事实作用范围。匹配依据为报告语义、关系词、引用对象与修饰作用域，不绑定公司、source ID、披露年月或某两个年份。
2. 本例可识别主体 `2026中期報告` 与附属 `有關2025年度報告的補充資料`。引用报告的 FY、2025、補充不参与主体的财年、财期、amended、选优或直接截止日；不把引用年度加入 coverage 或当作年度日历证据。
3. 不能完整识别关系、存在两个并列主体、主体本身多年份/多财期、类别与主体冲突、范围年不明或修订作用对象不明时，继续按既有严格规则保留未决。不能因为字符串含“及/有关/补充”就截尾，不能删去未解释的剩余内容；未支持的语法不自动归一。
4. 主体本身的“修訂/更正/補充”等仍影响 amended；只有明确修饰另一报告的附属部分被隔离。不要把“补充资料单独公告”误当作新主体半年报。
