## Findings

### 1-未修复-中-同批正文年度供证语义未在规则层显式，「现有邻近年度日历」可被实现为仅运行前证据，首次运行中期来源将无法确认

- **位置**: plan §5.2「六个月事实须与现有邻近年度日历相符后确认财年和 Q2」；关联 §1 表注与 §6 验收期望「unknown0」。
- **问题类型**: 契约缺失（供证时序语义）/ 测试缺口。
- **当前写法**: 「现有邻近年度日历」未定义是否包含同一批正文确认的年度事实；验证 3 的合成断言未覆盖零既有年度时的同批供证。
- **反例/失败场景**: 首次真实生产运行时，四来源均未发布 → `local_hk_annual_ends` 为空（`cn_download_workflow.py:273-275` 仅读已发布 meta）；窗口内四条标题均无年份 → `hk_annual_end_date` 不供证（`cn_report_selection.py:422-425`）。若实现者把年度锚限定为「运行前已存在的本地/远端标题证据」，两份中期（2025-06-30/2026-06-30）的 `fiscal_quarter_at` 因无 12 月年度锚返回 None，结果为 2 确认 + 2 unknown，与 §1 表「拟确认财年」四条全部确认及 §6「unknown0」验收期望矛盾。
- **为什么有问题**: 中期 Q2 的年度归属在本数据下唯一正确的锚是**同批正文确认的末期年度事实**（2024-12-31/2025-12-31，距中期均在 366 天内）。该供证链是验收达成的必要条件，但 5.2 的「现有」措辞可被读成排除同批事实；正确结果仅靠 §1 表间接锚定，规则层未闭合。
- **直接证据**: `cn_download_workflow.py:273-275`；`cn_report_selection.py:422-425`；`hk_fiscal_calendar.py:102-127`；`facts-verification.json`（四日期与相邻年末距离）；plan §1 表与 §6「预期……unknown0」。
- **影响**: 实施按字面实现 → 首次验收中期仍 unknown → 目标未达成、返工一轮；错误方向是安全失败关闭（不写错数据），但真实验收成本高。
- **建议改法和验证点**: 5.2 显式补一句：「年度锚集合在同一次 resolution 内包含本批正文确认的年度事实；同批内年度事实先确认、中期映射后消费，不以运行前已发布证据为限」。验证 3 增加显式断言：零本地年度 + 零窗口标题年度时，同批末期正文年度可供证中期 Q2 确认（用隔离 Fs 夹具）。
- **修复风险（低）**: 一句话规则补丁 + 一条夹具断言，不动结构。
- **严重程度（中）**: 直接影响已确认目标（四来源全部确认）的可实现性；不阻断计划整体方向，但应在实施放行前由 plan 补丁闭合。

### 2-未修复-低-正文获取 eligibility 对 resolver 失败原因的区分未落入验证断言，存在歧义/多主体来源被正文错误确认的可实现路径

- **位置**: plan §5.1/§5.2 准入规则；§6 验证 1 合成反例清单；验证 2 原则性表述。
- **问题类型**: 测试缺口（失败模式未显式断言）。
- **当前写法**: 规则层已禁止「已识别的多主体、显式年份/日期冲突、区间简写歧义」被正文覆盖，验证 2 写「不能由正文输入绕过原歧义」；但验证 1 的合成反例清单（比较期交换/无完整日期/声明冲突/正文身份错/分类冲突/非月末/扫描页/超预算）未显式包含「多主体标题来源」「区间简写标题来源」触发正文获取的场景。
- **反例/失败场景**: 当前 `resolve_hk_report_period` 对缺年份（`:693-703`）、多主体（`:677-679`）、区间简写（`:684`）、多年份（`:701`）均返回 None，外部不可区分。若实现把 eligibility 简化为「resolver 返回 None 即尝试正文」，9633 已拒绝的多主体/区间简写来源也会获取正文；正文若给出单一日期，将错误确认本应关闭的歧义，绕过 9633 已审防线。
- **为什么有问题**: 准入条件的判定需要区分「缺事实」与「歧义/冲突拒绝」；规则正确但验证网未钉住该失败模式，最简实现可通过现有断言清单。
- **直接证据**: `cn_report_selection.py:677-703`；`cn_report_selection.py:435-443`（uncertain 分支对全部 None 同构处理）；plan 验证 1 清单；plan 验证 2「9633 全部已审主体/引用/竞争主体断言保留」。
- **影响**: 实现跑偏 → 正文绕过 9633 歧义防线 → 回归；因 9633 既有测试在案，大概率被测试面拦截，但正文触发路径本身无断言。
- **建议改法和验证点**: 验证 1 补两条合成反例：(a) 多主体标题 + 可解析正文日期 → 仍拒绝、不产生确认事实、不计入已确认候选；(b) 区间简写标题 + 可解析正文日期 → 同上。eligibility 实现须复用主体/歧义判定或由 resolver 暴露失败原因，形状由实现者决定，代码审核核验。
- **修复风险（低）**: 仅补夹具断言。
- **严重程度（低）**: 规则层已禁止，9633 断言提供二级防护；补断言即可闭合。
