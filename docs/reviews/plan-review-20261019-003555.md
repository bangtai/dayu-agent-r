## 3. Findings

**本计划未发现阻断性 material finding。**

具体判断：

1. **方向足以指导目标实现**：计划要求由一个纯投影给出“可确认的主体标题”，并让财年、财期、amended、选优、直接截止日与本地 rebuild 共用同一投影。对目标而言，主体 `2026中期報告` 经现有 owner 路径可得 `fiscal_year=2026`、`identity_period=H1`、`covered=('H1',)`、`amended=false`、`report_date=null`；不会把附属 `2025年度報告` 的 FY/年份/補充带入主体，也不会合并为 Q2。
2. **范围没有明显过宽**：计划只要求一个纯投影，不强制新 dataclass/parser 框架/公共返回类型，不新增 PDF 正文输入、schema、存储格式、迁移或全库扫描；生产改动范围限定为 `cn_report_selection.py` 及必要的 `hk_download_rebuild.py` 调用点，其他 owner 只复用契约。这符合“最小化满足需求”。
3. **owner 消费者基本覆盖完整**：计划覆盖 `resolve_hk_report_period`、`_classify_hk_period_projection`、`_infer_hk_fiscal_year`、`_hk_title_years`、`has_unresolved_end_date`、`_is_hk_amended_title`、`_pick_best_hk_announcement`、`_build_hk_candidate`、`hk_annual_end_date`、`local_hk_annual_ends` 与 rebuild 的直接日期/年/期路径。没有发现其它生产模块独立解析港股标题。
4. **身份影响没有超出目标**：目标将获得新的 H1/2026 身份；七份既有来源通过 `(provider, source_id)` 匹配优先返回既有 document/internal identity，计划又用官方 2+2+16 行重放断言七份 source/年/期/coverage/amended 不变。`amended=false` 避免了把附属补充资料误当主体修订而生成 amended seed。
5. **严格歧义关闭被保留**：计划明确两个并列主体、缺失引用对象、缺失补充关系、主体内部多年份/多财期、类别与主体冲突、财年范围不明、坏/多截止日、修订作用域不明继续 unknown；不能因含“及/有關/補充”就截尾。现有测试中的冲突/歧义反例与 `_hk_report_family` 的 category-first 约束继续适用。
6. **历史与 PR203 保留可验证**：原失败六文件哈希、七份来源的完整 meta/revision/primary/文件字节、重复增量无新写入、固定入口源码 SHA 等都有明确验证命令或脚本；PR203 只作为 base 依赖，不重复纳入旧提交。

## 4. Open questions

1. **混合语言复合标题的 English-copy 过滤顺序**：`select_hkexnews_report_candidates` 在 `resolve_hk_report_period` 之前调用 `_is_english_hk_announcement`，后者扫描整条标题。若主体是中文、附属引用含 `ANNUAL REPORT` 等英文报告词，当前可能被当作英文副本直接跳过，而不是 unknown。目标标题是纯中文，未被该路径影响；计划也未把该过滤器列入消费者。建议实现时明确：是否让主体投影先于 English-copy 判定；若不做，记录为后续限制。
2. **`period_resolution_version` 是否随解析语义变化**：`hk_download_rebuild.py` 以 `_PERIOD_VERSION="hk-period-v3"` 写入 durable meta。计划的“不版本 bump”若仅指存储格式/全局下载版本，应明确；若 rebuild 的解析语义改变而版本仍为 v3，未来 rebuild 记录的算法来源会不准确。本任务不运行生产 rebuild，因此不是目标路径阻断项。
3. **`uncertain_hk_period` 的用户可见 retry hint 是否延后**：当前 `direct_event_text.py:283` 与 `ingestion_runtime.py:4411` 对所有 uncertain 统一提示“补齐可信年度截止日资料”，而计划已证明本目标即使有 `2025-12-31` 年度证据仍会拒绝。目标修复后该提示不再出现；若未来同类标题仍 unknown，提示会误导。建议明确归入后续 work unit，还是在本 slice 改为 cause-neutral 文案。
